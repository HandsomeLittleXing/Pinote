# 第一套「贴纸」皮肤冰箱贴布局与插画设计

> 日期：2026-11-19
> 状态：2026-11-19 用户已确认，明确要求 Android App 同步修改
> 范围：Windows 桌面端与 Android 手机端的第一套 `glass`／「贴纸」皮肤

> 后续视觉校正：用户指定手机端维持“第一行一张、其后两列错开”，并以本文预览图的黄、粉、绿、蓝纸色和暖色页面为参考。

## 1. 背景与目标

用户希望第一套皮肤的便签列表像贴在冰箱上的纸片：自动错落、有轻微倾斜和高低变化，不呈现机械网格。每张便签仍有简笔插画，进入该便签后也能看到同一幅插画底图；插画种类增加，参考用户提供的两张拙趣线稿截图，但不临摹其中的具体形象。

用户已确认使用**自动错落摆放**，不需要手动拖动或保存坐标。成功标准：

1. 第一套皮肤的默认列表在少量和大量便签时都有错落的冰箱贴节奏；排序、置顶、搜索和筛选结果保持可理解。
2. 桌面独立便签与手机编辑页显示与列表卡相同的便签专属线稿，且不会挡住文字、光标或操作。
3. 原创线稿从现有 8 款增至 16 款，题材包含生活小物、植物和动物；同一便签跨端与重启后选中同一款。
4. 深浅色、长文字、大字体、窄窗口和长列表仍可阅读与操作；其他两套皮肤不受影响。

视觉方向示意：[冰箱贴布局预览](./2026-11-19-sticker-fridge-layout-preview.png)，矢量源文件为同名 SVG。预览用于确认节奏、层级和插画位置，不代表最终像素稿。

## 2. 非目标

- 不提供自由拖拽、卡片坐标存储或多端位置同步。
- 不复制用户截图、喜茶或其他网站的插画；新增路径均为本项目原创。
- 不改便签正文、颜色、标签、提醒、待办的数据结构、数据库或同步协议。
- 不改变「硫酸纸」「小墨」两套皮肤的布局与插画规则。
- 不让卡片真实互相覆盖到影响点击、长按、菜单或无障碍焦点。

## 3. 现状分析与复用

| 范围 | 现状 | 复用与改进 |
| --- | --- | --- |
| 共享插画 | `src/shared/stickerDoodles.ts` 定义 8 组 SVG path，用便签 ID 哈希稳定选图 | 扩展至 16 组，保留 ID 选图接口和无持久化设计 |
| 桌面列表 | `src/renderer/components/StickerList.tsx` 默认用 `glass-note-grid`，首卡跨两列；`globals.css` 仅有约半度旋转 | 保留排序和首卡层级；按便签 ID 派生有限的倾角、错位、尺寸节奏 |
| 手机列表 | `mobile/src/screens/StickerListScreen.tsx` 仅在未筛选且 1–6 张时用双列，更多时回到单列 | 第一套皮肤默认列表在更多便签时继续错落展示，并保留 `FlatList` 虚拟化 |
| 卡片插画 | `StickerListItem.tsx` 与 `StickerCard.tsx` 已在卡片底层放一张 SVG | 继续复用同一选图函数，丰富题材、尺寸和靠边位置 |
| 桌面编辑 | `StickerEditor.tsx` 的 `.sticker-editor` 只放 Tiptap 内容，没有专属插画 | 在内容层后方放不响应指针的同款 SVG |
| 手机编辑 | `StickerEditorScreen.tsx` 的 `RichEditor` 是实色 WebView | 保持 WebView 实色背景，使用低对比度 SVG 背景图；换色时同步更新其 CSS |

第一套皮肤虽沿用内部 ID `glass`，展示名称已是「贴纸」。此前 `2026-11-03-glass-card-first-skin-design.md` 和 `2026-11-03-glass-saas-refinement-design.md` 对规则网格、无插画的描述，以本次用户要求为准修订；皮肤兼容和数据规则继续沿用。

## 4. 视觉与交互方案

### 4.1 列表排布

- 默认列表保留一张较大的首卡，其余卡片为双列纸片。手机在常见的 340dp 及以上宽度保持双列，右列略向下错开；更窄屏幕或系统字体明显放大时转单列。桌面仍沿用现有窄窗口断点。
- 通过一组有限的视觉模板产生轻微倾斜、左右位移、上边距和卡片高度差。模板由便签 ID 稳定决定；排序变化只改变卡片在列表中的顺序，不改变该卡的倾斜与插画。
- 倾斜以可读性为限，目标范围约 ±2°；位移和高度差通过留白吸收。纸片之间保持明确的点击间隔，不让阴影或变换裁切内容。
- 首卡可以更醒目，但不以固定的“横幅 + 完全等高小卡”呈现；卡片高度依标题、摘要和模板在安全范围内变化。
- 搜索、标签、置顶、待办、提醒和回收站等结果继续使用整齐的结果卡，便于扫描和比较；返回默认列表时恢复冰箱贴排布。
- 颜色点、轻纸边、柔和阴影提供“贴上去”的感觉；不增加拟真磁铁图片或影响操作的装饰物。
- 浅色贴纸主题使用预览图的暖灰页面、近白操作表面、深绿墨色；纸张色包含柔黄、浅粉、薄荷绿和淡蓝，并保留其余便签色的相近低饱和变体。

### 4.2 插画

- 保留现有杯子、小伙伴、花、星星、叶子、太阳、猫、信封 8 款；新增 8 款原创线稿，方向为兔子、鸭子、小象、鱼、蘑菇、云、铅笔、气球。线条略有不规则感，避免机械对称。
- 每张便签只选一幅主插画。卡片中让它主要占角落空白，编辑页放大但降低对比度；同一便签在桌面、手机、列表和编辑页保持同款。
- 线稿是背景装饰，不参与可访问性朗读与点击。标题、正文、提醒和待办信息始终在它上方；浅色与深色分别调整线稿颜色和透明度。
- 空白便签也显示线稿。长正文、搜索高亮和富文本自定义颜色下，优先保证文字可读，必要时进一步降低线稿对比度。

### 4.3 编辑页

- 桌面独立便签在 Tiptap 内容容器底层放一幅专属 SVG；收起态隐藏。线稿随容器裁切，不覆盖工具栏、菜单和拖动区域。
- 手机编辑页在 `RichEditor` 的 WebView 内容 CSS 中设置同款低对比度 SVG 背景图，保持当前实色背景、键盘行为和正文滚动。切换便签颜色、深浅模式或便签 ID 时同步更新背景图与文字色。
- 两端编辑区仍可完整选择、复制、编辑富文本；插画不作为正文 HTML 保存，也不会进入同步或 AI 输入。

## 5. 模块职责与接口数据

| 模块 | 职责 |
| --- | --- |
| `src/shared/stickerDoodles.ts` | 维护原创路径、稳定选图，以及可复用的展示模板标识；不依赖 React 或平台 |
| `src/renderer/components/StickerList.tsx`、`globals.css` | 桌面默认列表的排布与响应式间距；不修改排序数据 |
| `src/renderer/components/StickerListItem.tsx` | 桌面卡片使用模板与共享线稿；保留现有按钮、菜单和键盘操作 |
| `src/renderer/components/StickerEditor.tsx`、`sticker.css` | 桌面编辑区线稿层和可读性 |
| `mobile/src/screens/StickerListScreen.tsx`、`mobile/src/components/StickerCard.tsx` | 手机默认列表的虚拟化排布、卡片高度/倾角与点击区 |
| `mobile/src/screens/StickerEditorScreen.tsx` | WebView 内的线稿背景与颜色切换同步 |

输入为已有 `Sticker.id`、`Sticker.color`、当前皮肤和明暗模式；输出只影响视图样式与 SVG。`Sticker`、`AppSettings`、移动偏好、SQLite、服务端数据库、HTTP/IPC 和同步消息均不变。任何布局参数都不写入存储。

## 6. 边界与异常

- **零张／一张**：零张保留当前空状态；一张展示完整首卡，不出现空列。
- **大量便签**：手机继续用 `FlatList`，只计算可见卡片；插画为本地矢量路径，不加载网络图片。
- **短 ID、旧 ID、重复图案**：稳定哈希对任意字符串有结果；相邻卡偶然同图可以接受，16 款降低重复概率。不得依赖数组顺序生成随机数。
- **狭窄或大字体**：退回单列并减小倾角，避免标题、菜单与标签被裁切。
- **筛选和搜索**：结果列表保持阅读优先；切换视图不改便签排序或内容。
- **编辑器**：WebView 初始化前不注入命令；注入失败时仍显示可编辑的实色背景，不影响保存。
- **深色和低透明度**：线稿颜色随主题切换；桌面背景透明度仍只作用于纸面，不让正文变淡。

## 7. 风险、兼容与回退

主要风险是错位造成点击区域相邻、手机双列在小屏上拥挤，以及 WebView 背景图在某些 Android 版本上渲染不一致。用留白、单列断点和实色背景回退控制。原有 `glass` ID 与所有便签数据不变；若视觉不合适，可仅回退布局样式和装饰层，无数据迁移。

## 8. 验证策略

1. 桌面和手机分别检查 0、1、2、6、20 张便签；观察错落节奏、滚动、卡片点击、长按/菜单和首卡展示。
2. 检查排序、置顶、搜索、标签筛选和回收站；结果可扫描，返回默认列表后模板稳定。
3. 同一便签在两端列表与编辑页核对插画身份；切换颜色、明暗模式、重启后仍一致。
4. 检查长标题、长正文、待办、提醒、AI 标注、自定义文字色、系统大字体、窄桌面窗口和手机键盘。
5. 运行桌面与手机 TypeScript 检查、桌面构建和 Android 本地构建；实机可连接时复核编辑 WebView 背景与滚动。
