# 桌面端工具栏、图标和托盘修复设计

## 背景与目标

用户反馈便签顶栏的字体、字号等功能无法点击，Windows 任务栏和任务管理器仍显示旧图标，经快捷方式启动后通知区域可能没有应用图标，并希望应用摆脱“电脑便签/电脑标签”的旧名称。

本次桌面端统一使用新名称 **贴记（Pinote）**：中文表达随手贴下并记住，英文由 pin 与 note 组合。使用移动端现有的“笑脸笔记本”视觉作为 Windows 图标来源。成功标准：工具栏和更多菜单中的格式入口可点击且格式生效；安装后的 exe、窗口、任务栏、任务管理器、快捷方式使用新图标与名称；从安装快捷方式冷启动和已有实例再次启动时，托盘可用，点击可打开列表。

## 非目标

- 不修改便签内容的数据结构、云同步协议、移动端包标识或服务器标识。
- 不改变 Windows 对通知区域图标“始终显示”或折叠显示的用户设置；应用只能保证创建图标，不能强制固定到主任务栏。
- 不迁移既有用户数据目录，也不把历史内容中的旧名称批量替换。

## 现状分析

- `src/renderer/components/StickerEditor.tsx` 的顶栏含可选格式按钮、更多菜单和一个共用 `Popover`。浮层使用零宽 `PopoverAnchor`，格式入口通过 `setTimeout(..., 0)` 在 Radix 菜单关闭后打开；需要验证菜单关闭与弹层开启的焦点/外部点击时序。`src/renderer/styles/sticker.css` 将整个顶栏设为拖动区域，部分控件仅通过父容器的 `WebkitAppRegion: no-drag` 解除拖动，需验证所有按钮及弹层交互区域。
- `src/main/index.ts` 在 `whenReady` 后创建托盘，并通过单实例锁处理快捷方式的再次启动。`src/main/tray.ts` 在图标加载为空时直接返回，之后没有重试或替代图标。打包配置确实把 `resources/icon.ico` 放入 `resources`，当前解包目录也存在该文件，因此“快捷方式启动无托盘”的具体触发条件尚未复现。
- `electron-builder.yml` 的 `productName`、安装包名和快捷方式仍是旧品牌，`resources/icon.ico` 是旧的纸团笑脸，移动端 `mobile/assets/icon.png` 是新的笑脸笔记本。便签窗口在 `src/main/windows.ts` 未明确设置图标，面板窗口虽设置图标却使用旧资源。
- `README.md` 当前写为“FrostNote · 霜笺”，用户已明确否定“霜笺”。桌面 UI、标题、托盘提示和打包标识仍混用旧名称；`mobile/app.json` 的显示名称仍是“便签”。工作区已有大量未提交改动，包括 `StickerEditor.tsx`、`electron-builder.yml` 和 README；实现必须在当前版本上做局部修改，保留这些现有改动。

## 参考与复用

- 复用 `mobile/assets/icon.png` 的既有视觉，不新设计品牌图形；从同一源生成 Windows 多尺寸 `.ico`，并为小尺寸托盘保留清晰轮廓。
- 复用 `src/main/tray.ts` 的现有菜单和 `src/main/windows.ts` 的窗口创建流程。
- 复用 `src/renderer/components/ui/Popover.tsx` 与 `DropdownMenu.tsx`，仅调整调用方式和所需的交互边界。

## 实现思路

1. 先在桌面开发构建中复现顶栏点击：分别检查常驻格式按钮、更多菜单的字体颜色/字号、选择文字后的应用结果、窄窗口和收起状态。根据实际触发点修正拖动区域和菜单至浮层的切换时序，让所有控件有可靠的非拖动命中区，保留便签可拖动能力。
2. 以移动端笔记本图标为源生成 Windows 多分辨率图标，供 exe、安装器、卸载器、窗口和托盘共用。校验 `.ico` 包含适合 16/32/48/256 像素显示的帧，避免缩小纸团图造成不可辨识。
3. 对外显示名称统一为“贴记”，英文产品名使用 `Pinote`。调整桌面打包产品名、快捷方式、窗口标题、关于页、托盘文案、移动端应用显示名及 README 的品牌介绍。保持内部 `sticker-note` 包名及 `com.stickernote.app`、`com.stickernote.mobile` 标识，避免用户数据目录和系统升级身份突变；若安装器因产品名变化产生并存风险，验证安装升级行为并在交付说明中明确处理方式。
4. 托盘启动路径增加可观测的图标加载/创建结果与安全替代图标，确保冷启动时不会因一个资源加载失败而静默无托盘；检查二次启动时现有实例的托盘状态。通过打包版快捷方式做实际启动验证，并区分“图标没创建”和“被 Windows 收入折叠菜单”。

## 职责边界

- `StickerEditor.tsx` 与 `sticker.css`：负责顶栏点击、拖动及浮层状态，不处理主进程托盘。
- `src/main/tray.ts`：负责创建、维护与销毁通知区域图标及菜单，不改变 Windows 的显示偏好。
- `src/main/index.ts`：负责进程生命周期和单实例行为；`src/main/windows.ts`：负责窗口图标和标题。
- `electron-builder.yml`、`resources/`：负责安装产物名称和图标；桌面渲染 UI 文案只负责用户可见品牌；`mobile/app.json` 只调整移动端显示名。

## 接口与数据

不新增 IPC、数据库字段或持久化设置。现有便签 JSON、同步数据与 `sticker-note` 用户数据路径保持兼容。仅桌面显示名、静态图标资源、安装产物名和窗口/托盘运行行为变化。

## 边界与异常

- 无选中文本时的字号/颜色操作沿用 Tiptap 当前输入格式行为；有选区时应用到选区。编辑器未就绪时相应菜单项保持禁用。
- 便签窄到隐藏可选按钮时，更多菜单仍能进入字号、颜色和格式；收起状态仍可展开。
- 图标资源不存在或无法读取时记录明确错误，并尝试从 exe/备用资源取得有效图标；重复创建托盘前先检查现有实例，避免双图标。
- 已运行实例被快捷方式再次启动时应聚焦列表，不应创建第二进程或丢失托盘。若 Windows 将图标折叠，向用户说明系统设置位置。

## 风险与兼容性

安装包改名不会自动删除桌面上用户自行保留的旧快捷方式；Windows 图标缓存也可能短期显示旧图标。保留内部应用身份以降低数据迁移风险。现有工作区未提交的编辑器和打包配置改动与本需求重叠，实现时需逐段核对差异，避免覆盖。

## 验证策略

- 运行桌面类型检查与构建；在开发版实际点击各工具栏功能，检查富文本结果与弹层焦点。
- 构建 Windows 解包版/安装包，检查 exe 图标、窗口图标、任务管理器显示、安装快捷方式名称与图标。
- 从安装快捷方式冷启动、退出后重启、运行中再次启动；逐项检查通知区域、折叠菜单、右键菜单和点击打开列表。
- 核对原有便签数据读取、开机启动配置及旧安装升级后的行为。
