# 桌面便签滚动、AI 浮层、主题字体与图标修复设计

## 背景与目标

用户在桌面便签截图中指出：便签底部的横向滚动条始终可见；AI 分析结果浮层没有完整显示；希望「硫酸纸」和「小墨」使用常规字体。随后明确指定桌面端图标来源为 `resources/icon-source.jpg`。目标是在不改变便签内容的前提下，让便签正文只在内容超高时纵向滚动，AI 结果在不同窗口尺寸下完整可达，让手写体仅用于「贴纸」主题，并使桌面端各入口使用指定图标。

成功标准：短内容便签无底部横向滚动条，长内容仍可纵向滚动；AI 摘要、标注、标签、提醒、待办与重新整理按钮均可查看和点击；贴纸主题继续使用莲生灵光体，另两套主题显示系统常规字体；桌面 exe、窗口、托盘、安装器与快捷方式使用从指定 JPG 生成的图标。

## 非目标

- 不删除右下角用于提示原生缩放的点阵角标，不改变窗口拖动或缩放方式。
- 不修改 AI 分析结果、便签正文、标签、提醒的数据结构和业务规则。
- 不改手机端的字体与布局，也不新增字体设置项。
- 不改变手机端图标、应用标识和用户数据目录。

## 现状分析

- `src/renderer/components/StickerEditor.tsx` 的正文容器使用 `overflow-y-auto`。`src/renderer/styles/sticker.css` 中贴纸背景 SVG 定位为 `right: -9px`、`bottom: -12px`，且经过旋转；它可能扩大正文容器的横向滚动范围。截图底部红框显示的是横向滚动条，代码探索尚未通过运行时测量确认唯一触发元素。
- 同一组件通过零宽 `PopoverAnchor` 打开 AI 结果。`src/renderer/components/ui/Popover.tsx` 将浮层宽度限制为窗口宽减 20px、最大 260px，并加 `p-3` 与纵向滚动；`AiResultPanel.tsx` 又给内容设最多 260px 的固定宽度、最多 420px 高度及纵向滚动。内容宽度与外层内边距叠加，且两个容器都可滚动，是截图中裁切和双滚动风险的明确来源。
- `src/renderer/styles/globals.css` 在 `html, body, #root` 上全局使用莲生灵光体，`useTheme.ts` 已把当前皮肤设在 `<html data-skin>`。目前没有按皮肤切换桌面字体的规则。
- `scripts/generate-desktop-icon.py` 当前从 `mobile/assets/icon.png` 生成桌面 `resources/icon.png` 和七种尺寸的 `resources/icon.ico`。`electron-builder.yml` 将该 ICO 用于 exe、安装器、卸载器并复制到运行资源目录，窗口与托盘再从资源目录加载。指定的 `resources/icon-source.jpg` 是白底纸团笑脸图，与当前笔记本图不同。
- 相关代码已包含用户先前的未提交布局和字体改动。本次只围绕上述元素修改，不覆盖其他工作树编辑。现有项目无针对便签溢出或 AI 浮层尺寸的自动化测试。

## 参考与复用

- 继续使用 `useTheme.ts` 的 `data-skin`，不添加新的主题状态或设置字段。
- 复用 `Popover.tsx` 的 Radix 碰撞边界与 Portal，使浮层在窗口内重新定位。
- 保留 `sticker.css` 的原生缩放角标、正文滚动容器与贴纸背景 SVG，仅约束会导致横向溢出的视觉层。
- 沿用现有桌面图标生成脚本和打包资源路径；只换生成源与产物，不另加一套图标加载逻辑。

## 实现思路

1. 在开发窗口检查正文容器的 `clientWidth`、`scrollWidth` 和溢出元素，分别使用短文本、长英文、增大字号及不同便签宽度复现。若截图底部条来自正文横向溢出，约束背景插画在可视区域内，并让长文本换行；正文只保留必要的纵向滚动。保留右下角缩放提示。
2. 让 AI 结果面板宽度随浮层内容区收缩，不再叠加固定 260px 与外层内边距；只由浮层一层负责高度上限和纵向滚动。AI 标签、长摘要和提醒文字允许换行；窗口较小时通过 Radix 碰撞处理与滚动访问完整内容，不让底部按钮被永久裁切。
3. 用桌面 CSS 的皮肤变量控制字体：贴纸继续使用莲生灵光体；硫酸纸与小墨使用 Windows 系统 UI 字体优先的常规字体栈。浮层挂在 `body` 下，也应继承当前主题字体；不改变用户在富文本中主动指定的字号和颜色。
4. 将桌面图标生成脚本的输入改为 `resources/icon-source.jpg`，按图形边界裁切并保留适当留白，重新生成 `resources/icon.png` 与含 16、24、32、48、64、128、256 像素帧的 `resources/icon.ico`。保持打包配置与窗口/托盘加载路径统一；在打包产物中检查 exe 图标和安装资源图标。Windows 可能保留旧任务栏缓存，验收应以新安装和重新启动后的实际显示为准。

## 职责边界

| 文件 | 职责 |
| --- | --- |
| `StickerEditor.tsx`、`sticker.css` | 便签正文可滚动区域、背景插画的视觉边界与窗口内显示；不处理 AI 数据。 |
| `AiResultPanel.tsx` | AI 结果内容的响应式宽度、文字换行与可点击区域；不改变结果生成或采纳逻辑。 |
| `ui/Popover.tsx` | 通用浮层的窗口边界、高度和滚动约束；若通用规则影响其他菜单，改为由 AI 浮层的调用点提供专用类。 |
| `globals.css` | 桌面端各皮肤的字体继承规则；不调整手机端和字体文件。 |
| `scripts/generate-desktop-icon.py`、`resources/icon.png`、`resources/icon.ico` | 从指定 JPG 生成桌面图标；不改变手机端资源。 |
| `electron-builder.yml`、`src/main/windows.ts`、`src/main/tray.ts` | 继续消费统一的 `resources/icon.ico`，仅核对链路，不另设图标来源。 |

## 接口与数据

不新增或变更 React 属性、IPC、持久化设置、数据库、同步协议与便签 JSON。输入为现有皮肤 ID、窗口尺寸、正文、AI 结果及桌面图标源图；输出为 CSS 布局、字体呈现与构建时生成的桌面静态图标。

## 边界与异常

- 短内容与大窗口：不出现无意义的横向或纵向滚动条。
- 超长文字、链接、大字号与长列表：正文按宽度换行，可纵向访问全部内容；不遮住窗口缩放角标。
- 便签窄窗口或高度不足：AI 浮层可在窗口内调整位置，内容通过单一滚动区域访问；标题和操作按钮保持可点击。
- AI 结果为空、只有摘要、或同时含多标签/提醒/待办：均不留多余滚动条；文字不超出卡片边界。
- 三套主题的明暗模式和设置页、列表页、便签页：字体一致切换，贴纸保留手写感；字体文件加载失败时回退系统字体。
- 指定 JPG 缺失、全白或无法解析时：图标生成明确失败，不静默沿用旧 ICO；16px 小图仍能辨认纸团笑脸。

## 风险与兼容性

修改通用 `Popover` 可能影响颜色、提醒、字号等其他浮层，因此优先让 AI 结果局部适配，只有确认通用规则有问题才调整公共组件。禁止简单隐藏全部滚动条来掩盖内容不可达。字体切换只影响展示，既有富文本 HTML 和存储保持原样。桌面图标改变会改变 Windows 外观但不应改变应用 ID 和数据路径；系统图标缓存可能延迟反映新资源。若运行时证明底部条来源不同，先更新此文档中的原因与修复范围再实施。

## 验证策略

- 在贴纸主题的短/长便签、约 240×200 与约 660×390 窗口中检查正文的横纵向滚动、背景插画及右下角缩放。
- 在小窗、标准窗、大窗打开有完整 AI 结果的浮层，检查摘要、标注、标签、提醒、待办与底部按钮都可见或可滚动到，且无横向溢出和双滚动。
- 切换三套主题及明暗模式，检查便签、列表、设置和浮层的字体；确认富文本自定义字号和颜色不受影响。
- 检查生成后的 ICO 七个尺寸与 PNG 预览；构建后核对 exe、安装器、窗口、托盘和新建快捷方式的图标来自该源图，手机图标保持原样。
- 运行 `npm run typecheck` 和桌面构建；检查相关差异及 `git diff --check`，保留已有未提交改动。
