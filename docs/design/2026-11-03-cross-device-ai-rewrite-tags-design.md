# 跨端 AI 配置、便签整理补充与精简标签设计

> 日期：2026-11-03；按 2026-11-04 的补充需求修订
> 状态：已确认并实施
> 范围：桌面端、Android 端、同步服务端

## 1. 背景与目标

目前 AI Key 只能写入服务端 `.env`，桌面和手机的设置页只能开关 AI。AI 整理只生成摘要、标注、标签和提醒建议，不能整理原便签正文或给出可写入的补充内容。每次生成 2–6 个标签，客户端还提供“全部采纳”，标签积累后筛选栏难以使用。

本次目标：在任一已配对设备上配置一次 Key，同一同步空间的桌面和手机都可使用；在两端编辑页把原文纠错并整理为清晰结构，同时提出有用的补充建议；AI 标签以少量、可复用、可查找为原则。AI 不自动改写正文，也不自动将补充内容或建议标签加入便签。

成功标准：任一端设置/删除 Key 后另一端状态更新且看不到明文；整理稿与 AI 新增建议可分别查看，用户可只应用整理或选择补充项后应用；正文变化时旧提案不能覆盖新内容；单次最多建议 2 个标签，便签已有 3 个或更多标签时不再新增 AI 标签；列表筛选不因标签总量增加而无限铺开。

## 2. 非目标

- 不让模型自动后台修改便签、不批量改写所有便签、不做自动标签迁移或删除既有标签。
- 不在本期提供多模型、任意 Base URL 或用量结算配置；继续使用服务端现有 `LLM_BASE_URL`、`LLM_MODEL`。
- 不把 API Key 放进普通便签同步载荷、SQLite、`electron-store` 设置或 AI 返回结果。
- 不承诺完整保留原富文本的字体、颜色和内嵌媒体；有图片或嵌入内容的便签本期不提供一键替换。
- 不自动检索网络资料或将未经核实的外部事实写成确定结论；需要日期、金额、联系人等具体信息时，以待确认问题呈现。

## 3. 现状与复用

| 范围 | 现状 | 复用入口 |
| --- | --- | --- |
| 凭据与调用 | `server/src/services/llm.ts` 从 `LLM_API_KEY` 读取 Key；`server/src/routes/ai.ts` 仅有状态和标注接口 | 复用同步空间认证 `requireAuth`、限流及现有 LLM 代理 |
| 桌面 | `AiSettings.tsx` 只显示配置状态；`src/main/sync.ts` 经主进程请求 AI | 增加受控 IPC，渲染进程不持久化 Key |
| 手机 | `SettingsScreen.tsx` 只有 AI 开关；`mobile/src/api/aiClient.ts` 使用配对 token | 复用现有认证请求和设置页分区 |
| 正文 | 桌面 Tiptap、手机 RichEditor 存储 HTML；`AIAnnotation` 与正文分离 | 复用 `Sticker.content`、内容哈希、原有保存和同步链路 |
| 标签 | `server/src/services/llm.ts` 提示 2–6 个；服务端和共享解析器最多接收 6 个；两端可全部采纳 | 复用 `Sticker.tags`、现有标签输入和筛选组件 |

## 4. 交互方案

### 4.1 Key 设置

桌面和手机的“AI 整理”设置分区加入密码输入、显示/隐藏、保存、测试连接、移除操作；保存后只显示“已配置”和末尾 4 位。每次打开设置页重新读取服务端状态。未配对时显示先连接同步服务的状态，不提供虚假的本地保存。保存时不将明文写入客户端日志、偏好设置或便签同步；输入框在请求结束后清空。

同一同步空间共用一个 Key。任一已配对设备更新时覆盖该空间先前的 Key。旧 `LLM_API_KEY` 作为部署迁移期的后备来源；删除空间 Key 后，若存在服务器默认 Key，状态切换为“服务器默认”，否则为“未配置”。状态接口明确返回来源，避免删除后误判 AI 是否可用。

### 4.2 整理与补充正文

编辑页提供独立的“AI 整理并补充”命令，与当前“AI 整理/标注”并列。模型先纠正原文中可判断的错别字、标点和语序，整理为短标题、段落、项目列表，不删除有意义内容；再根据原文给出最多 3 条补充建议，例如可执行的下一步、遗漏的检查项、帮助说明主题的例子或需要确认的问题。补充可以扩展原文思路，但不能虚构已经发生的事、确定日期/金额/联系人或替用户作出承诺。

结果分为“整理后的原文”和“AI 补充建议”，不把新增内容伪装成原文。桌面并排对照原文与整理稿，手机切换“原文/整理稿”；补充项单独列出，可逐条勾选。预览默认勾选补充项，但用户可全部取消并只应用整理。应用时，选中的新增内容放在便签末尾的“补充建议”小节中，便于日后辨认和修改。没有有价值的补充时返回空列表，不凑数。

用户点“应用整理”或“应用整理与补充”后才写入 `Sticker.content`，同时清空原正文对应的过期 `ai` 标注，并沿用现有同步流程。编辑会话保留一次原 HTML 快照供“撤销本次整理”；退出后不提供跨会话版本历史。若生成后正文又有变化，禁用应用并提示重新生成。含图片或嵌入节点的正文禁用一键替换；普通加粗、链接等格式可能被新结构替换，预览中明确提示。

### 4.3 标签收敛与查找

单次 AI 最多建议 2 个短标签，优先从当前同步空间已有标签中复用，避免“工作/工作事项/待办工作”等近义变体。建议与现有标签去重；便签标签少于 3 个时才允许采纳，且最多补到 3 个。已有超过 3 个的老便签保持原状，可手动删改。两端取消无上限“全部采纳”，改为“采纳可用建议”。

列表只固定展示少量高频标签及当前选中标签，其余放入可搜索的“更多标签”菜单；搜索继续匹配便签正文和标签。高频排序仅影响展示，不改动标签数据。老 AI 结果中多余的标签保留在数据中，但界面最多显示前 2 个建议。

## 5. 端到端路径与职责

| 模块 | 职责 |
| --- | --- |
| `server/src/routes/ai.ts` | 认证、限流、Key 状态/保存/测试/移除、整理补充请求；不返回 Key 明文 |
| 服务端凭据存储模块与 `server/src/services/llm.ts` | 按 `sync_space_id` 读取并解密 Key，调用现有模型；Key 不进入日志或缓存键 |
| 服务端 AI 校验与共享 HTML 渲染模块 | 区分原文整理块和新增建议，严格校验数量与长度、转义文本、只输出允许的 HTML 标签；标签去重和数量上限 |
| `src/main/sync.ts`、IPC、preload | 桌面端网络与凭据操作；渲染进程只接收状态和操作结果 |
| `mobile/src/api/aiClient.ts` | 手机端经认证请求配置与改写接口；不持久化 Key |
| 两端设置页、编辑页、AI 结果组件 | 配置表单、原文对照、补充项选择、应用/撤销、受限标签采纳和可搜索筛选 |

## 6. 接口与数据

已有 `GET /ai/status` 扩展为 `{ configured, model, source: "space" | "server" | "none", keyHint?: string }`，不包含明文。新增 `PUT /ai/key`（`{ apiKey }`，仅接受非空、限定长度的字符串）、`POST /ai/key/test`（测试当前已保存 Key）、`DELETE /ai/key`。均需配对 token；写入接口只在 HTTPS 上传输，localhost 开发环境例外。

新增 `POST /ai/rewrite`，输入 `{ plainText, contentHash }`，输出 `{ sourceHash, organizedBlocks, supplements }`。`organizedBlocks` 为原文整理稿，只允许 `heading | paragraph | bullet` 的纯文本块；`supplements` 为最多 3 条 `{ id, kind: "suggestion" | "example" | "question", text }`，与原文块分开。服务端校验输入长度、块数、补充条数与总长度，不接收模型生成的 HTML。共享渲染器把两部分转义并生成受限 HTML，按用户勾选的补充项拼成最终预览与正文。补充建议不作为已证实事实输出。

`Sticker` 模型不加字段。应用整理稿及选中补充时更新现有 `content`、`updatedAt` 并将 `ai` 置为 `null`；`tags` 保持现值。Key 使用按同步空间隔离的新表，AES-256-GCM 加密，部署方需配置独立的 `AI_CREDENTIALS_MASTER_KEY`（32 字节随机密钥的 Base64 编码），不复用数据库密码。密钥轮换须先用旧密钥解密并重新加密数据库记录；丢失主密钥时需由用户重新输入 AI Key。

```sql
CREATE TABLE IF NOT EXISTS `ai_credentials` (
  `sync_space_id` CHAR(36) NOT NULL COMMENT '所属同步空间，唯一配置一份 AI 凭据',
  `encrypted_key` VARBINARY(1024) NULL COMMENT 'AES-256-GCM 加密的 API Key；移除时清空',
  `iv` BINARY(12) NULL COMMENT 'GCM 随机初始化向量；移除时清空',
  `auth_tag` BINARY(16) NULL COMMENT 'GCM 认证标签；移除时清空',
  `key_hint` CHAR(4) NULL COMMENT '仅用于界面遮罩显示的末尾四位；移除时清空',
  `is_deleted` TINYINT(1) UNSIGNED DEFAULT 0 NOT NULL COMMENT '是否删除 0-否 1-是',
  `create_time` DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) COMMENT '创建时间',
  `update_time` DATETIME(3) NULL COMMENT '最近一次更新或移除时间',
  PRIMARY KEY (`sync_space_id`),
  CONSTRAINT `fk_ai_credentials_sync_space` FOREIGN KEY (`sync_space_id`)
    REFERENCES `sync_spaces` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

迁移为幂等建表；无须搬迁旧 `.env` 明文。已配置环境变量的现有部署继续可用；空间配置优先。API Key 绝不进入 `stickers.ai`、同步响应、崩溃日志或前端持久化。

## 7. 边界与异常

- Key 为空、长度超限、模型返回 401/429、服务超时或主密钥缺失时给出可操作错误；保存操作失败不改变现有凭据。测试调用不会把测试文本写入便签。
- 同一空间两台设备同时保存 Key 时以后成功提交者为准；状态界面再次打开或刷新后显示最新来源与末尾四位。
- 便签空白、超过 AI 输入上限、含嵌入媒体或整理稿为空时不提供应用；生成与应用之间内容哈希不同则拒绝旧提案。
- AI 可能误改原意或提出不适用的补充。预览必须显示完整整理稿、清楚标出新增建议并要求手动确认；用户可取消任意补充项。“撤销本次整理”只作用于当前编辑会话。
- 对原文没有足够信息的补充，以“待确认”问题表达；模型无合理建议时允许零补充。服务端拒绝超量、空白或格式非法的新增内容。
- 模型仍可能返回过量、重复或不相关标签。服务端强制最多 2 个，客户端再次限量、去重并检查单便签总数；旧数据不丢弃。

## 8. 风险、兼容与验证

Key 入库使服务端主密钥和 HTTPS 成为配置前提，需要将主密钥纳入部署备份与轮换流程。编辑器替换 HTML 有格式损失风险，以仅文本块、完整预览和会话内撤销控制。AI 补充内容可能不准确，以与原文分区、逐条选择和不编造确定事实控制。新客户端兼容旧 `GET /ai/status` 字段缺失并提示服务端升级；服务端继续支持旧客户端的 `/ai/annotate`。旧便签和已有标签不迁移。

验证覆盖：凭据保存/覆盖/移除、跨端状态一致、各同步空间隔离、错误 Key 与离线失败、敏感信息不出现在日志/响应；整理与补充正常路径、零补充、逐条取消、只应用整理、空白与长文本、并发编辑、HTML 转义、富文本/媒体边界、应用与撤销及跨端同步；0、1、2、3、超过 3 个既有标签的采纳边界和标签菜单搜索。执行共享 TypeScript、服务端测试、桌面构建、Android 构建及两端实机交互检查。
